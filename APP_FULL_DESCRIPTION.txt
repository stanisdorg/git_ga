# Полное техническое описание приложения QA Voice Assistant

## 1. Общее описание (Overview)
QA Voice Assistant — это одностраничное веб-приложение (SPA/PWA), предназначенное для организации, запоминания и повторения знаний методом интервальных повторений (Spaced Repetition System - SRS). Приложение сфокусировано на вопросах и ответах для подготовки к техническим интервью (QA/DevOps), но может использоваться для любых знаний.
Работает полностью на стороне клиента в браузере (или в Electron-обертке), взаимодействуя с легковесным локальным Node.js сервером для персистентности данных (чтение/запись JSON-файлов).

## 2. Дизайн и UI/UX (Design System)

### 2.1. Цветовая палитра (Color Palette)
Приложение использует темную тему по умолчанию для снижения нагрузки на глаза.
*   **Фон страницы (`--color-bg`):** `#1a1a1a` (Почти черный, основной фон).
*   **Фон карточек (`--color-card`):** `#242424` (Темно-серый, выделение блоков).
*   **Границы (`--color-border`):** `#333333` (Тонкие разделители).
*   **Текст основной (`--color-text`):** `#ffffff` (Белый).
*   **Текст вторичный (`--color-text-secondary`):** `rgba(255, 255, 255, 0.7)` (Светло-серый, для метаданных).
*   **Акцентные цвета:**
    *   **Зеленый:** `#2e7d32` (Кнопка "Восстановить", "Сохранить", индикатор успеха).
    *   **Красный:** `#d32f2f` (Кнопка "Удалить", "Удалить навсегда", запись голоса).
    *   **Оранжевый:** `#fb923c` (Избранное, "Звездочка").
    *   **Синий:** `#3b82f6` (Прогресс-бары).
*   **Состояния наведения:** Осветление фона или изменение прозрачности (`rgba(255, 255, 255, 0.1)`).

### 2.2. Типографика
*   **Шрифт:** Системный стек (`-apple-system`, `BlinkMacSystemFont`, `Segoe UI`, `Roboto`, etc.) для максимальной производительности и нативности.
*   **Размеры:**
    *   Вопросы: `16px`, `font-weight: 500`.
    *   Ответы: `14px`, `line-height: 1.5` (для читаемости).
    *   Метки (Badges): `10px`, `uppercase` (для компактности).

### 2.3. Компоненты UI

#### 2.3.1. Навигация (Tabs Navigation)
*   **Табы Категорий:** Горизонтальный скроллируемый список сверху. Активная категория подсвечивается.
*   **Подкатегории:** Отображаются как "чипсы" (chips) под табами категорий. Позволяют быстро фильтровать контент внутри категории.
*   **Сайдбар (Sidebar):**
    *   Слева (на десктопе).
    *   Содержит историю поиска и режимы ("История", "Транскрипция").
    *   Скрывается/раскрывается кнопкой-тогглом.
    *   На мобильных устройствах скрыт по умолчанию.

#### 2.3.2. Карточка вопроса (Question Card)
*   **Отображение:** Блок с вопросом (жирный) и ответом (серый текст).
*   **Метаданные:** Снизу карточки — метки категории/подкатегории.
*   **Действия:**
    *   **Звездочка (Избранное):** Справа сверху.
    *   **Меню (Три точки):** Вызывает контекстное меню ("Редактировать", "Дублировать", "Удалить").
*   **Инлайн-редактор (Edit Mode):**
    *   Открывается прямо в карточке.
    *   Поля: Категория (Select), Подкатегория (Select), Вопрос (Textarea), Ответ (Textarea).
    *   Поля адаптируются по ширине, поле ответа имеет увеличенную высоту (300px+).
    *   Кнопка сохранения (дискета) внизу справа.

#### 2.3.3. Панель Корзины (Trash Panel)
*   Видна только в режиме редактирования (`Edit Mode`).
*   Располагается слева (вместо сайдбара навигации).
*   Содержит список удаленных карточек.
*   Действия для каждой карточки: "Восстановить" (Зеленая) и "Удалить навсегда" (Красная).

#### 2.3.4. Режим обучения (Learn Mode / SRS)
*   Полноэкранный оверлей (`#learn-container`).
*   **Лицевая сторона:** Только вопрос.
*   **Оборотная сторона:** Ответ + Кнопки оценки ("Снова", "Трудно", "Хорошо", "Легко").
*   **Прогресс:** XP бар сверху, показывающий опыт за сессию.

#### 2.3.5. Страница Статистики (Statistics Page)
Представляет собой отдельный полноэкранный модуль (`#stats`), перекрывающий основной интерфейс (`z-index: 2000`). Реализована в `srs/stats-ui.js`. Использует выделенный набор CSS-переменных (`--st-*`) для темизации.

**Цветовая Палитра (CSS Variables):**
*   **Backgrounds:** `--st-bg: #0E1117` (Main), `--st-surf: #161B22` (Surface), `--st-surf-h: #1F2630` (Hover).
*   **Accents:** `--st-prim: #FF9F1C` (Orange), `--st-sec: #2EC4B6` (Teal), `--st-danger: #E5533D` (Red).
*   **Text:** `--st-text: #E6EDF3`, `--st-muted: #8B949E`.

**Адаптивная Сетка (Layout & Grid):**
*   **Mobile (<1024px):**
    *   Контейнер: `max-width: 600px`, `flex-direction: column`.
    *   Отступы: `padding: 32px`, снизу `100px` (под Sticky CTA).
    *   Достижения: Сетка 2 колонки (`grid-template-columns: repeat(2, 1fr)`).
*   **Desktop (≥1024px):**
    *   Контейнер: `max-width: 1280px`, Grid Layout (`grid-template-columns: 2fr 1fr`).
    *   **Row 1 (Full):** Header + Hero Section (объединены).
    *   **Row 2 (Full):** Progress Cards (3 в ряд).
    *   **Row 3 (Columns):** Activity (Left) | Difficulty + Categories (Right).
    *   **Row 4 (Full):** Achievements (4 колонки).
    *   Особенности: CTA кнопка перемещается внутрь Hero-секции, аккордеоны (Difficulty/Categories) принудительно раскрыты.

**Компоненты и Детальная Реализация:**

1.  **Header (Верхняя панель):**
    *   Заголовок: "Статистика" (18px, bold).
    *   Кнопки: `Home` (закрывает слой), `Auth` (статус логина), `Version` (v1.49).

2.  **Hero Section (Сводка):**
    *   **Level Progress:** Полоса (`height: 10px`, `bg: --st-surf-h`) с заполнением (`bg: --st-prim`), анимируется (`transition: width 0.5s`).
    *   **Metrics Row:**
        *   🔥 **Streak:** Текущая серия (из `metrics.streakCurrent`).
        *   ⏱ **Time:** Расчетное время = `ceil(sessionCount * 1.5)` мин.
        *   📚 **Cards:** Карточек пройдено сегодня (фильтр по `lastReviewed === today`).
    *   **Sticky CTA (Mobile Only):**
        *   Позиционирование: `fixed bottom: 0`, градиентный фон (`transparent` -> `st-bg`).
        *   Кнопка: "НАЧАТЬ ОБУЧЕНИЕ" или "УЧИТЬ ВСЕ" (Cram). Тень: `0 4px 12px rgba(255, 159, 28, 0.3)`.

3.  **Short Progress (Карточки метрик):**
    *   Стек из 3 блоков:
        *   **Осталось:** `Remaining / Total`.
        *   **Прогноз:** Дата завершения (`Date.now() + Remaining / Speed`). `Speed` = 12 карт/день (fallback) или `xp / 50`.
        *   **Цель:** Дней до финиша.

4.  **Difficulty Distribution (Сложность):**
    *   **Сегментация (по Ease Factor):**
        *   🔴 **Очень трудные:** EF < 1.7 (Color: `--st-danger`).
        *   🟠 **Трудные:** 1.7 ≤ EF < 2.1 (Color: `--st-prim`).
        *   🟢 **Стандарт:** 2.1 ≤ EF < 2.4 (Color: `--st-sec`).
        *   🔵 **Легкие:** EF ≥ 2.4 (Color: `#2f81f7`).
    *   **UI:** Collapsible Header (стрелка `rotate(180deg)`), Bar Chart (общая полоса), List (детальный список с счетчиками).
    *   **Interactivity:** Клик по категории открывает **Modal**.
        *   **Modal:** Overlay (`backdrop-filter: blur(4px)`). Список вопросов/ответов. Кнопка "Train" запускает `startLearnSession(cards, { mode: 'cram' })`.

5.  **Activity Chart (Активность):**
    *   **Tabs:** Week / Month / Year. Активный таб: `bg: --st-surf-h`, `color: #fff`.
    *   **Chart:** Flexbox-диаграмма (`align-items: flex-end`).
    *   **Bars:** Столбцы XP. Текущий день выделен белым (`#fff`), остальные прозрачные (`opacity: 0.8`). Высота рассчитывается относительно максимума в периоде.

6.  **Categories (Категории):**
    *   Логика: Топ-5 категорий + "Показать ещё" (скрытые элементы).
    *   Визуализация: Название + Процент изученности + Progress Bar (`bg: --st-sec`).

7.  **Achievements (Достижения):**
    *   **Grid:** Карточки с иконками (28px).
    *   **States:**
        *   🔒 **Locked:** `opacity: 0.4`, `filter: grayscale(100%)`.
        *   🔓 **Unlocked:** `opacity: 1`, `bg: rgba(46, 196, 182, 0.05)`, border color `--st-sec`.
    *   **Types:** "Первый шаг" (1 урок), "В огне" (7 дней стрик), "Снайпер" (90% точность), "Эрудит" (50 карт).

## 3. Функциональность и Логика

### 3.1. Система хранения данных (Data Layer)
*   **Источник правды:** JSON файлы в папке `data/` на сервере.
*   **`questions_no_anki.json`:** Основная база вопросов. Структура:
    ```json
    [
      {
        "category": "DevOps",
        "subcategory": "CI/CD",
        "question": "...",
        "answer": "..."
      }
    ]
    ```
*   **`user_progress.json`:** Хранит SRS-состояние для каждого пользователя. Ключ — текст вопроса (или ID). Данные: `interval` (интервал), `easeFactor` (множитель легкости), `nextReviewDate` (дата следующего повторения), `history` (история ответов).
*   **Синхронизация:** При загрузке страницы фронтенд запрашивает данные с `/metadata` и `/api/progress`. При изменениях отправляет `POST` запросы на `/save` или `/api/progress`.

### 3.2. Алгоритм SRS (Spaced Repetition)
Реализован в `srs/algorithm.js`. Основан на вариации SM-2.
*   **Оценки:**
    *   `1 (AGAIN)`: Сброс интервала, `EF` уменьшается на 0.25.
    *   `2 (HARD)`: Интервал растет медленно (x1.2), `EF` уменьшается на 0.15.
    *   `3 (GOOD)`: Интервал = Интервал * EF, `EF` не меняется.
    *   `4 (EASY)`: Интервал растет сильно, `EF` увеличивается на 0.05.
*   **Ease Factor (EF):** Определяет "сложность" карточки. Диапазон: 1.3 (очень сложно) — 2.9 (очень легко).
*   **Уровни сложности:**
    *   `VERY_HARD`: EF < 1.7
    *   `HARD`: 1.7 <= EF < 2.1
    *   `STANDARD`: 2.1 <= EF < 2.4
    *   `EASY`: EF >= 2.4

### 3.3. Планировщик (Scheduler)
Реализован в `srs/scheduler.js`.
*   **Цель:** Изучить базу за 60 дней (константа `GOAL_DAYS`).
*   **Ежедневный лимит:** Динамически рассчитывает, сколько новых карточек нужно учить в день, чтобы успеть к дедлайну (обычно 10-15 карт).
*   **Очередь:** Смешивает карточки для повторения (Due) и новые карточки (New) в одну сессию.

### 3.4. Поиск и Голосовой ввод
*   **Поиск:** Фильтрация "на лету" по вхождению подстроки в вопрос или ответ. Подсветка найденных терминов не реализована (просто фильтрация списка).
*   **STT (Speech-to-Text):**
    *   Использует Web Speech API (`webkitSpeechRecognition`).
    *   Кнопка микрофона в строке поиска.
    *   Режим "Транскрипция" в сайдбаре: непрерывно слушает и записывает текст, позволяя использовать его как заметки.

### 3.5. Редактирование и "Мягкое" удаление
*   **Soft Delete:** При удалении карточки она не стирается из JSON мгновенно, а помечается флагом или переносится в массив `trash` в памяти (на клиенте) и синхронизируется с сервером.
*   **Корзина:** Позволяет отменить удаление. Кнопка "Удалить навсегда" вызывает API для физического удаления из файла.

## 4. Архитектура Кода

### 4.1. Модульность (ES Modules)
Приложение не использует сборщики (Webpack/Vite) в рантайме, полагаясь на нативные ES Modules (`import ... from ...`). Это упрощает отладку и деплой.
*   **`ui-manager.js`:** Оркестратор. Отвечает за инициализацию, проверку версий (cache busting через `?v=...`) и переключение глобальных экранов.
*   **`tabs-navigation.js`:** "Толстый" контроллер представления. Отвечает за рендеринг списка карточек, фильтрацию, обработку кликов, логику драг-н-дропа (если есть) и редактирования.

### 4.2. Бэкенд (Node.js)
*   **`server.js`:** Простой HTTP-сервер без фреймворков (Express не используется для минимизации зависимостей).
*   **Роутинг:** Ручной парсинг `req.url` и `req.method`.
*   **Безопасность данных:** Перед каждой перезаписью файла создается резервная копия `.bak`.

## 5. Технические особенности и Ограничения
*   **PWA:** Есть `manifest.json` и `sw.js` (Service Worker) для кэширования статики, что позволяет работать офлайн (если данные предзагружены).
*   **Производительность:** При большом количестве карточек (1000+) рендеринг всех карточек в DOM может быть тяжелым. Виртуализация списка не используется, но есть пагинация/ленивая загрузка (частично).
*   **Синхронизация:** Конфликты редактирования (если открыть в двух вкладках) решаются по принципу "последний записал" (LWW), сложного мерджа нет.

## 6. Инструкции по разработке (Dev Guidelines)
*   **Git Flow:** Авто-пуш после каждого атомарного изменения. Сообщения коммитов на русском.
*   **Versioning:** Версия `APP_VERSION` в `ui-manager.js` должна инкрементироваться при любом изменении JS/CSS для сброса браузерного кэша у клиентов.
*   **Backup:** Команда `npm run backup` создает полный архив папки `data/` в `_backups/`.
