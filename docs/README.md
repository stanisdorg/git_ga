**Как использовать:**

- Используйте как отправную точку для изучения системы

---

### 2. Swagger UI (`docs/swagger.html`)

**Что это:** Интерактивная документция для REST API

**Что внутри:**
- Все 25+ эндпоинтов сгруппированы по тегам:
  - **Authentication** — login, register, GitHub/Google/Telegram OAuth
  - **Cards** — создание и обновление карточек
  - **Data** — загрузка и сохранение данных
  - **Progress** — SRS прогресс, статистика, достижения
  - **Trash** — корзина карточек
  - **Metadata** — порядок колод и карточек
  - **Admin** — логи сервера
  - **Webhooks** — Telegram Bot Webhook
  - **System** — системные эндпоинты

**Как использовать:**
1. Откройте `docs/swagger.html` в браузере
2. Кликните на эндпоинт для просмотра деталей
3. Нажмите **"Try it out"** для тестирования запроса
4. Заполните параметры и нажмите **"Execute"**
5. Увидите реальный ответ сервера

**Пример:**
```
1. Раскройте POST /api/login
2. Нажмите "Try it out"
3. Введите в body:
   {
     "username": "jeff",
     "password": "mypassword"
   }
4. Нажмите "Execute"
5. Увидите ответ: { "ok": true, "username": "jeff", "role": "editor" }
```

### 3. Mermaid-диаграммы (`docs/diagrams.md`)

**Что это:** 8 визуальных диаграмм архитектуры

**Что внутри:**
1. **Общая архитектура (C4 Context)** — все компоненты системы и связи
2. **Последовательность аутентификации** — как работает вход (Login + GitHub OAuth)
3. **Поток данных карточек** — от UI до файлового хранилища
4. **Компоненты SRS** — алгоритм интервального повторения
5. **Жизненный цикл карточки** — state diagram (создана → активна → изучена → в корзине → удалена)
6. **ER-модель данных** — структура базы данных (users, user_data, metadata, trash)
7. **Последовательность SRS** — как сохраняется прогресс обучения
8. **Deployment Diagram** — схема развертывания (Cloudflare → Reg.ru → Node.js)

**Как использовать:**
- Откройте файл в GitHub/GitLab — диаграммы отрендерятся автоматически
- Или используйте Mermaid Live Editor: https://mermaid.live
- Скопируйте код диаграммы и вставьте в редактор

### 4. D2 Architecture (`docs/architecture.d2`)

**Что это:** Интерактивная архитектурная схема

**Что внутри:**
- Клиентские приложения (PWA, Electron, Mobile)
- Серверные модули (Auth, Cards, Data, SRS, Admin, Webhooks)
- Хранилище данных (JSON файлы)
- Внешние сервисы (GitHub, Google, Telegram, Sentry)
- Все связи между компонентами

**Как использовать:**
1. Откройте https://play.d2lang.com
2. Скопируйте содержимое `docs/architecture.d2`
3. Вставьте в редактор
4. Увидите красивую интерактивную схему

**Или установите D2 локально:**
```bash
# macOS
brew install d2

# Linux
curl -fsSL https://d2lang.com/install.sh | sh -s --

# Затем запустите:
d2 docs/architecture.d2 --watch
```

### 5. OpenAPI Specification (`docs/openapi.yaml`)

**Что это:** Машиночитаемая спецификация API

**Что внутри:**
- Полная OpenAPI 3.0 спецификация
- Все эндпоинты с параметрами, запросами и ответами
- Схемы данных (Card, User, Progress, и т.д.)
- Теги для группировки
- Примеры запросов и ответов

**Как использовать:**
- **Генерация клиентов:**
  ```bash
  openapi-generator-cli generate -i docs/openapi.yaml -g javascript -o ./client
  ```
- **Генерация моков:**
  ```bash
  prism mock docs/openapi.yaml
  ```
- **Валидация:**
  ```bash
  swagger-cli validate docs/openapi.yaml
  ```

## 🎯 Сценарии использования

### Сценарий 1: Новый разработчик присоединяется к команде

1. **День 1:** Откройте `docs/index.html` → прочитайте обзор
2. **День 1:** Откройте `docs/diagrams.md` → изучите архитектуру
3. **День 2:** Откройте `docs/swagger.html` → протестируйте API
4. **День 2:** Запустите `node server.js` → попробуйте приложение
5. **День 3:** Изучите код, используя документацию как справочник

### Сценарий 2: QA инженер тестирует API

1. Откройте `docs/swagger.html`
2. Раскройте нужный эндпоинт (например, POST /api/card/create)
3. Нажмите "Try it out"
4. Заполните тело запроса
5. Нажмите "Execute"
6. Проверьте ответ сервера
7. Повторите для всех эндпоинтов

### Сценарий 3: Frontend разработчик интегрирует API

1. Откройте `docs/openapi.yaml`
2. Сгенерируйте JavaScript клиент:
   ```bash
   npx @openapitools/openapi-generator-cli generate \
     -i docs/openapi.yaml \
     -g javascript \
     -o ./api-client
   ```
3. Используйте сгенерированный клиент в коде

### Сценарий 4: Менеджер хочет понять архитектуру

1. Откройте `docs/index.html` → раздел "Архитектура системы"
2. Посмотрите 4 блока компонентов
3. Откройте `docs/diagrams.md` → диаграмма 1 (общая архитектура)
4. Всё понятно без знания кода!

## 🆘 Troubleshooting

### Swagger UI не загружается?
- Откройте консоль браузера (F12)
- Проверьте, что нет CORS ошибок
- Попробуйте открыть через локальный сервер:
  ```bash
  cd docs
  python -m http.server 9000
  # Откройте http://localhost:9000/swagger.html
  ```

### Mermaid-диаграммы не рендерятся?
- В GitHub/GitLab они работают автоматически
- Локально используйте https://mermaid.live
- Или установите VS Code расширение

### D2-диаграмма не открывается?
- Используйте https://play.d2lang.com
- Скопируйте содержимое `docs/architecture.d2`
- Вставьте в редактор

## 📝 Обновление документации

При добавлении новых эндпоинтов:

1. **Добавьте swagger-jsdoc комментарий в server.js:**
   ```javascript
   /**
    * @openapi
    * /api/new-endpoint:
    *   post:
    *     tags: [Tag]
    *     summary: Описание
    *     ...
    */
   ```

2. **Обновите `docs/openapi.yaml`** — добавьте новый эндпоинт

3. **Перезапустите Swagger UI** — изменения появятся автоматически

4. **Добавьте диаграмму в `docs/diagrams.md`** если нужно
